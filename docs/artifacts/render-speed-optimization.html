Render-Speed Optimization — Social Media Export

Source of truth: docs/plans/render-speed-optimization.md. Three fixes are already in the working tree (pending commit, parity-proven); eight slices remain. Bench fixture recipe lives in the plan doc.

Prime directive: every speed change ships with proof that output quality is unchanged — bit-identical where the change claims neutrality (PSNR inf + frame MD5), explicitly flagged and approved where it isn't.

1 · Measured evidence — M1 Pro, 60 s 1080×1920@30 fixture

The wall every scenario hits is the hardware decode floor: one VideoToolbox decode session = 7.9 s for this clip. The engine already sits at ffmpeg parity ~1.6 s above it. Chunked parallelism is a no-op on M1 Pro (one media engine) — it exists for Max (2 encode engines) and Ultra (4).

2 · Landed this session — working tree, pending commit

Semaphore-dispose SIGTRAP fix

Engine.swift · ParallelEngine.swift — inflight semaphores created at 0 and primed with signals; the final drain no longer leaves the value below creation value, which libdispatch traps on dispose.

Before: every render exited 133 after [done]; parallel engine died mid-run with no output. The Node bridge papered over it with a wrong root-cause comment.

was: exit 133now: exit 0parallel completes

Rect-scoped overlay dispatch

FilterGraph.composite + overlay_composite kernel — composite passes dispatch only the overlay's rect instead of the full 2-megapixel canvas; kernel offsets gid by the integer-snapped origin.

~99 % thread reduction per logo / text overlay per frame; identical pixel set processed.

PSNR inf vs baselineframe MD5 equal

libass detect_change caching

LibassRenderer.renderTexture — when libass reports the subtitle frame unchanged, the CPU blend + ~8 MB upload are skipped and the cached texture returned. Uploads rotate an 8-slot texture ring (fixes a latent in-flight tearing race); scratch buffer reused.

Bench fixture: 24 recomposes instead of 1800.

PSNR inf vs baselinering ≥ inflight+1

S5

Dirty-rect subtitle compose + upload

quality-neutralblocked by: S2 · pairs after S3

Track the union bbox of ASS_Image rects per changed frame; zero/blend/replace() only that region (plus the previous frame's box so stale glyphs clear); pass the bbox to graph.composite so the GPU pass shrinks from full canvas to caption-sized. This is the karaoke-content win, where detect_change fires every frame.

  • Pixel parity vs S1 on bench fixture AND a karaoke ASS
  • Measured subtitle-path CPU reduction on karaoke job (report numbers)
S6

Edge blur: fix strength, then separable

step 1 changes pixels intentionallyblocked by: S2

Step 1 (audit finding): tap stride must be sigma / EFF_SIGMA (σ/3), not sigma / KERNEL_R (σ/6) — the kernel currently renders at half the requested Gaussian sigma vs the CSS/ffmpeg preview. Step 2: replace the 169-tap 2D grid with a two-pass separable Gaussian (~6× fewer band-pixel taps), matching the fixed 2D reference within float tolerance.

  • Rendered strength matches CSS backdrop-filter: blur(σ) preview side-by-side
  • Separable ≈ 2D reference (PSNR > 55 dB on bands; no banding at σ ∈ {5, 30, 100})
  • Band-pass GPU time reported before/after

size win, speed-neutralblocked by: S1

S8

Bridge: honest exit codes

correctnessblocked by: S1 published

Once v0.1.4 is the published floor, drop the bridge's "any exit is success if a [done] blob was seen" workaround (its comment misattributes the SIGTRAP to AVFoundation teardown — real cause was the semaphore trap, now fixed). Reject on nonzero exit; keep [done] parse for stats only.

  • Nonzero engine exit rejects the bridge promise with the code
  • Forced failure (bad input path) surfaces a real error to the host

4 · Open questions — resolve before the dependent slice

Q1 · Chunked-encode acceptability

Chunk boundaries restart rate control → chunked ≠ single output (~33 dB between them; both valid encodes of identical pixels). OK for delivery renders, or draft-only? Product-owner decision gates S3 making chunking automatic.

Q2 · Multi-media-engine test hardware

S3's speedup claim needs a Max/Ultra machine or CI runner; none was available this session.

Q3 · Media-engine count detection

No public API exposes encode-engine count; likely a chip-name lookup table. Acceptable?

5 · Out of scope

  • Software encoders (x264/x265) — different quality/speed regime, breaks the GPU-resident design.
  • Lowering encode quality for speed — the draft profile already exists for that.
  • Editor preview/scrub performance — export path only.
  • Audit findings not folded into S4/S6.
